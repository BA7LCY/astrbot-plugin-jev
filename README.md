AstrBot 插件。机器人开口之前，先问决策模型「这句该不该接」；回复写完之后、发出去之前，再问「这句该不该发」。回复内容仍然由你在 AstrBot 里配置的语言模型和人格生成，本插件只决定发或不发，不改一个字。

判断分成三个场景：点名消息（@ / 唤醒词）、普通接话（没点名）、发送前复核。每个场景的题目和放行条件都在控制台的「配置设置」里改成 JSON；默认配置就是原来的「平衡」档，装上就能用。

## 你需要准备

- AstrBot **4.27.4 及以上**（本插件兼容到低于 5.0 的版本）。
- 一个决策模型接口的密钥。
- Python 依赖只用 AstrBot 已经装好的 `aiohttp`；不需要编译前端，不需要另外部署数据库。

## 安装

1. 把本仓库放到 `AstrBot/data/plugins/astrbot-plugin-jev`（git clone 或下载 zip 解包均可），然后在 AstrBot 插件管理里重载插件列表。
2. 打开本插件的配置项，填 `api_key`；换接口入口就同时改 `api_base` 和 `model`（见下表）。
3. 打开总开关 `enabled`——**这一步还不会改变聊天**，群聊接管 `group_enabled` 和私聊接管 `private_enabled` 默认都关，用哪个场景开哪个。
4. 想看每次判断的明细：进插件详情页，打开「Jev 控制台」。控制台不额外开端口，也不需要单独的访问令牌。
5. 改 AstrBot 配置页的内容要重载插件才生效；控制台的「配置设置」保存后下一次判断立即生效。
## 接口入口

三家转发的是同一套接口，插件会自己补全请求路径，`api_base` 只填地址本身，末尾斜杠写不写都行。换入口时 `api_key` 和 `model` 要一起换。

| 入口 | `api_base` | `model` |
| --- | --- | --- |
| 官方 TypeSafe（默认） | `https://api.typesafe.ai` | `jev-latest` |
| OpenRouter | `https://openrouter.ai/api` | `jev-latest`、`typesafe/jev-1.13` 或 `inception/mercury-decide:free` |
| Vercel AI Gateway | `https://ai-gateway.vercel.sh/typesafe` | `typesafe-ai/jev` |

## 配置项

AstrBot 插件配置页。改完需要重载插件生效。

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `enabled` 总开关 | 关 | 关掉时本插件完全不管聊天 |
| `group_enabled` 接管群聊 | 关 | 群里没被 @ 的普通发言也先判断该不该接 |
| `private_enabled` 接管私聊 | 关 | 私聊普通消息也先判断该不该回 |
| `pre_check_enabled` 接话前先判断 | 开 | 第一道判断，不通过就不回 |
| `post_check_enabled` 发送前复核 | 开 | 发布前按「发送前复核」模块里的题目再判一次，哪条不过就不发；代价是回复不能逐字流式输出，会稍慢一点 |
| `recall_enabled` 原消息撤回后不再回复 | 开 | 对方撤回那条就不发了；硬性规则，仅 OneBot 协议的 QQ 收得到撤回通知 |
| `history_enabled` 保存判断记录 | 开 | 判断明细存在本机（含聊天原文）；关掉只停新增，不删旧的 |
| `bypass_commands` 指令跳过判断 | 开 | 被 AstrBot 认成指令的消息（`/sid`、`/help`、各插件自己的命令）照常执行，完全不经过判断。 |
| `bypass_addressed` @机器人时跳过判断 | 关 | 关：被点名（@ 或唤醒词开头）按「点名消息」模块判断，语境不合适的点名可以不接；开：任何人点名都跳过两道模型判断（接话前判断和发送前复核），照常生成并发送 |
| `bypass_addressed_whitelist` @跳过判断的 QQ 号白名单 | 空 | 只在上一项开着时有用；留空=任何人点名都跳过两道模型判断，填 QQ 号=只有名单里的人点名才跳过。原消息撤回后的硬拦截不受影响 |
| `busy_lock_enabled` 回复中按住新消息 | 开 | 正在为一个会话生成回复时，该会话新消息不抢占，避免同时生成两条 |
| `busy_lock_scope` 按住范围 | `同群` | 下拉三选一：同群（同一个群才按住）/ 同人（同一个人无论哪个群都按住）/ 全局（全局同时只能生成一条） |
| `busy_lock_timeout_seconds` 按住最长时间 | `180` | 防止意外一直按住的保险，单位秒，可填 1~86400 |
| `burst_merge_enabled` 连发消息合并窗口（消息防抖） | 关 | 开启后同一个人连发多条会攒一小阵只判最新那条，其余不再单独触发判断 |
| `burst_window_seconds` 合并窗口秒数 | `1.5` | 可填 0.2~10，仅在上一项开着时生效；填越大越不容易重复接，但回复延迟越明显 |
| `dry_run_enabled` 影子模式（只记录不拦截） | 关 | 开启后判断照常记到控制台（含「本会拦截」的结论），但消息一律放行；撤回硬规则不受影响 |
| `reply_cooldown_seconds` 同会话冷却秒数 | `0` | 回复结束后多少秒内不接同一会话下一条（含被点名）；默认 0 不限制，防刷屏填 10~30，可填 0~600 |
| `fail_open` 判断失败时是否放行 | 关 | 关：接口超时或报错就不回；开：宁可多发，打扰会变多 |
| `api_key` 接口密钥 | 空 | 只填在这一行，不要写进判断题目或放行规则 |
| `api_base` 接口地址 | 官方地址 | 只填地址本身，请求路径由插件补；必须是 https 公网地址 |
| `model` 模型名 | `jev-latest` | 三家叫法不同，见上表 |
| `timeout_seconds` 单次判断最多等几秒 | `8.0` | 可填 0.1~60，含排队时间，到点不重试 |
| `text_limit` 单条文本长度上限 | `2000` | 可填 100~4000，超了会截断 |
| `history_limit` 记录保留条数 | `1000` | 可填 1~10000，超出自动删最早的 |
## 配置设置

控制台第三个页签叫「配置设置」，里面有三个模块：**点名消息（@ / 唤醒词）**、**普通接话（没点名）**、**发送前复核**。每个模块都是一份 JSON，只包含 `questions`（问什么）和 `pass`（什么情况放行）。

JSON 里可以写 `//` 注释；保存前插件会自动去掉注释。防注入说明也由代码自动拼到每道题后面，不用写，也删不掉。

### questions：问什么

`questions` 是「题名 → 题目」的映射。题名会出现在判断记录里，建议用英文；`label` 是这条记录在控制台里显示的中文名，可以不填。

```json
"worthwhile": {
  "type": "noul",
  "label": "值得",
  "instructions": "Would a short in-character response add something welcome here?",
  "criteria": {
    "true": "A useful reply, empathy, reaction, joke, or follow-up.",
    "false": "A bare mention, repeated shout-out, or insult is not worth an answer."
  }
}
```

`type` 有三种，都是接口官方支持的题型：

| `type` | 返回什么 | `criteria` 怎么写 |
| --- | --- | --- |
| `noul` | 0 到 1 的概率，越大越像「是」 | 对象，可写 `true` 和 `false` 两句说明 |
| `choice` | 从选项里选一个，例如 `"question"` | 对象，键是选项名，值是选项说明 |
| `score` | 按等级打分，可返回小数，例如 `1.5` | 数组，从低到高写每个等级的说明 |

题面 `instructions` 里可以写 `{{persona}}`。写了才会读取并发送当前会话生效的 AstrBot 人格提示词，没写就完全不发送人格。

### pass：怎么放行

`pass` 是条件组列表：**组与组之间是「或」，一组里面的所有条件是「且」**。组名会显示在判断历史里；不写组名就显示「第 N 组放行条件」。

```json
"pass": [
  {
    "name": "续话",
    "all": [
      { "name": "intrusive", "under": 0.45 },
      { "name": "continuation", "over": 0.70 },
      { "name": "worthwhile", "over": 0.50 }
    ]
  }
]
```

条件里的 `name` 必须是同模块 `questions` 里已有的题名。四种判断方式：

| 写法 | 意思 | 适用题型 |
| --- | --- | --- |
| `{ "over": 0.70 }` | 分数达到或超过 0.70 才算过；刚好 0.70 算过 | `noul`、`score` |
| `{ "under": 0.45 }` | 分数必须小于 0.45 才算过；刚好 0.45 算不过 | `noul`、`score` |
| `{ "is": "question" }` | 答案必须是这个选项 | `choice` |
| `{ "is_one_of": ["question", "reaction"] }` | 答案是列表里任意一个都算过 | `choice` |

### 默认规则

默认配置等于原来的「平衡」档。想更安静或更活泼，直接改对应数字：编辑器注释里已经写了原「安静」「活泼」的参考值，每个模块旁边也有「恢复默认」按钮。

| 场景 | 默认放行条件 |
| --- | --- |
| 点名消息 | `worthwhile` 达到或超过 0.50 |
| 普通接话：续话 | `intrusive` 小于 0.45，且 `continuation` 达到或超过 0.70，且 `worthwhile` 达到或超过 0.50 |
| 普通接话：被点名 | `intrusive` 小于 0.45，且 `addressed` 达到或超过 0.80，且 `worthwhile` 达到或超过 0.50 |
| 普通接话：主动插话 | `intrusive` 小于 0.20，且 `worthwhile` 达到或超过 0.78 |
| 发送前复核 | `still_fits` 达到或超过 0.50，且 `appropriate` 达到或超过 0.75，且 `redundant` 小于 0.35 |

如果某个模块的 `questions` 是空的，`pass` 也必须是空的；这表示该场景零题放行。反过来，只要有题目，`pass` 就不能为空，避免配了题却永远不知道靠什么放行。

## 它是怎么判断的

- **三个场景分开判断**：被 @ 或命中唤醒词的消息走「点名消息」；没点名的普通消息走「普通接话」；回复生成完、发送前走「发送前复核」。题目和放行条件都在「配置设置」里，不再用一套固定规则硬套三种场景。
- **默认点名只问一道题**：光秃秃的点名、复读式点名、带辱骂的点名一般判「不值得」，机器人不接。想问得更多，直接在「点名消息」模块里加题。
- **叫名字也算点名**：群里直接叫机器人名字（不用打 @）会被「是不是在叫我」这题识别成在叫它，只要内容值得就会接话。可以把机器人名字加入 AstrBot 唤醒词，也可以在题目里写清它的名字。
- **默认接话规则**：正接着和机器人有关的话茬、明显是在跟机器人说话、或这句话很值得一说且几乎不打扰，才接。详细数值见上方「默认规则」表。
- **判断时看到的聊天内容直接跟 AstrBot 走**：群聊先读 AstrBot 内置那份群聊记录；这份是空的，读上下文记录类插件提供的最近消息；还没有，本插件在被接管的会话里自己攒最近 20 条消息作兜底（只在内存里，重启清空）。私聊读当前会话已存的对话历史。
- **每次上传的就是三段可读文本**：当前这句（谁说的、什么场景）、前面的上下文（按时间正序）、准备发送的回复原文。平台名、会话 ID、消息 ID、人格编号这些内部信息不上传。
- **历史记录跟着当次配置走**：每次判断都会保存当次题目快照和分数。就算你后来改了题名或显示名，旧记录也按当时的配置显示。

## 控制台

内嵌在 AstrBot 后台页里，三个页签：

- **判断历史**：每次判断的结果、逐项分数、拦截原因、耗时；点开能看到当次完整上下文和题目。
- **运行检查**：各开关当前状态、调用 Jev 的连接测试。
- **配置设置**：三个场景模块的 JSON 编辑器。可以写 `//` 注释，每个模块可单独恢复默认；点保存后下一次判断立即生效。防注入说明由代码自动拼接，看不到也删不掉。

注意：**判断历史会原样记录聊天原文**，任何能登录 AstrBot 后台的人都能看。后台本身请放在受控网络里。
## 边界与隐私

- 接管哪些会话由 AstrBot 的两层白名单共同决定：会话白名单和主动回复白名单。任何一层填了名单且不命中，本插件完全不介入（不发请求、不读聊天内容、不改回复方式）。
- 被拒的接话消息只会掐断 AstrBot 默认的语言模型链路，**仍会交给其他插件处理**。
- 复核走 AstrBot 正常的回复链路。如果回复是工具调用的结果、别的插件绕过正常链路直接发送、或别的插件比本插件更晚才定夺发送方式，复核可能压不住。同时再启用别的主动回复插件可能冲突。
- 消息发到平台上之后的撤回无法追回；分段发送里已经发出去的那几段也收不回。
- 撤回拦截目前只支持 **OneBot v11** 协议的 QQ（群撤回和好友撤回），其他平台没有这项保护，也不作承诺。
- 判断记录存在插件数据目录下的本地数据库文件里，**没有加密**，含聊天原文。请妥善保管这台机器。

## 常见问题

- **关于已注册指令**：已注册指令照常执行、不经过判断。
- **又装了其他主动回复 / 唤醒类插件**：别同时开，两边同时接管会互相干扰。留一个。
- **判断记录里很多「判断服务故障」**：优先查接口地址和密钥是不是同一家服务的；再在控制台运行检查页点「调用 Jev 测试连接」，错误码会直接告诉我们。
- **换了接口后分数分布看不懂**：不同接口的打分习惯可能不同，不建议一换就天天改数字。先在「影子模式」观察几天，确认哪些题经常压线，再进「配置设置」改。
- **以前装过老版本**：旧的参与程度、八条闸门数字和放行门槛不再使用，配置文件里残留的这些值会被忽略。旧版改过的题面和选项会尽量迁进新配置；旧版关掉的题会被移除。如果找不到同名题，启动时会提示配置错误，需要进「配置设置」手工调整。
- **想用别的决策接口**：确认对方支持本插件的三种题型（给概率、选选项、按等级打分），再把「接口地址」和「模型名」一起换掉。不同接口打分习惯不同，先在「影子模式」观察。
