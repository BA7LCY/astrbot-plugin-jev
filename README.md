# Jev 接话判断

AstrBot 插件。机器人开口之前，先问决策模型一句「这句该不该接」；回复写完之后、发出去之前，再问一句「这句该不该发」。回复内容仍然由你在 AstrBot 里配置的语言模型和人格生成，本插件只决定发或不发，不改一个字。

七道题的分数按固定规则合成放行结论，一句话概括：不是在跟机器人说话、又可能打断别人时，不说。

仓库地址：https://github.com/BA7LCY/astrbot-plugin-jev

## 你需要准备

- AstrBot **4.27.4 及以上**（本插件兼容到低于 5.0 的版本）。
- 一个决策模型接口的密钥。
- Python 依赖只用 AstrBot 已经装好的 `aiohttp`；不需要编译前端，不需要另外部署数据库。

## 安装

1. 把本仓库放到 `AstrBot/data/plugins/astrbot-plugin-jev`（git clone 或下载 zip 解包均可），然后在 AstrBot 插件管理里重载插件列表。
2. 打开本插件的配置项，填 `api_key`；换接口入口就同时改 `api_base` 和 `model`（见下表）。
3. 打开总开关 `enabled`——**这一步还不会改变聊天**，群聊接管 `group_enabled` 和私聊接管 `private_enabled` 默认都关，用哪个场景开哪个。
4. 想看每次判断的明细：进插件详情页，打开「Jev 控制台」。控制台不额外开端口，也不需要单独的访问令牌。
5. 改 AstrBot 配置页的内容要重载插件才生效；控制台的聊天偏好、题目覆写保存后下一次判断立即生效。
## 接口入口

三家转发的是同一套接口，插件会自己补全请求路径，`api_base` 只填地址本身，末尾斜杠写不写都行。换入口时 `api_key` 和 `model` 要一起换。

| 入口 | `api_base` | `model` |
| --- | --- | --- |
| 官方 TypeSafe（默认） | `https://api.typesafe.ai` | `jev-latest` |
| OpenRouter | `https://openrouter.ai/api` | `jev-latest` 或 `typesafe/jev-1.13` |
| Vercel AI Gateway | `https://ai-gateway.vercel.sh/typesafe` | `typesafe-ai/jev` |

## 配置项

AstrBot 插件配置页。改完需要重载插件生效。

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `enabled` 总开关 | 关 | 关掉时本插件完全不管聊天 |
| `group_enabled` 接管群聊 | 关 | 群里没被 @ 的普通发言也先判断该不该接 |
| `private_enabled` 接管私聊 | 关 | 私聊普通消息也先判断该不该回 |
| `pre_check_enabled` 接话前先判断 | 开 | 第一道判断，不通过就不回 |
| `post_check_enabled` 发送前复核 | 开 | 发布前再问 Jev 三句：还合时宜（生成期间来的新消息没让草稿过时）、合适、不重复，哪句不过就不发；代价是回复不能逐字流式输出，会稍慢一点 |
| `recall_enabled` 原消息撤回后不再回复 | 开 | 对方撤回那条就不发了；硬性规则，仅 OneBot 协议的 QQ 收得到撤回通知 |
| `history_enabled` 保存判断记录 | 开 | 判断明细存在本机（含聊天原文）；关掉只停新增，不删旧的 |
| `bypass_commands` 指令跳过判断 | 开 | 被 AstrBot 认成指令的消息（`/sid`、`/help`、各插件自己的命令）照常执行，完全不经过判断。 |
| `bypass_addressed` @机器人时跳过判断 | 关 | 关：被点名（@ 或唤醒词开头）只问一道「值不值得开口」，语境不合适的点名可以不接；开：任何人点名都直接照常回复，不问 Jev |
| `bypass_addressed_whitelist` @跳过判断的 QQ 号白名单 | 空 | 只在上一项开着时有用；留空=任何人点名都跳过，填 QQ 号=只有名单里的人点名才跳过 |
| `busy_lock_enabled` 回复中按住新消息 | 开 | 正在为一个会话生成回复时，该会话新消息不抢占，避免同时生成两条 |
| `busy_lock_scope` 按住范围 | `同群` | 下拉三选一：同群（同一个群才按住）/ 同人（同一个人无论哪个群都按住）/ 全局（全局同时只能生成一条） |
| `busy_lock_timeout_seconds` 按住最长时间 | `180` | 防止意外一直按住的保险，单位秒，可填 1~86400 |
| `reply_style` 参与程度 | `平衡` | 下拉三选一：安静 / 平衡 / 活泼；同时决定接话起评分和跟随它的预设闸门（数值见下方「预设闸门数值」表） |
| `custom_gates_enabled` 自定义闸门数值（高级） | 关 | 默认关=闸门跟随参与程度预设，开箱即用；开=下面 `custom_gates` 折叠组里自填的八条档线生效；关掉即回到预设 |
| `custom_gates` 自定义闸门数值 | 折叠组 | 面板里收成一个可收起的分组，只有上一项开着才生效；逐项说明看组内每一项的提示 |
| `burst_merge_enabled` 连发消息合并窗口（消息防抖） | 关 | 开启后同一个人连发多条会攒一小阵只判最新那条，其余不再单独触发判断 |
| `burst_window_seconds` 合并窗口秒数 | `1.5` | 可填 0.2~10，仅在上一项开着时生效；填越大越不容易重复接，但回复延迟越明显 |
| `dry_run_enabled` 影子模式（只记录不拦截） | 关 | 开启后判断照常记到控制台（含「本会拦截」的结论），但消息一律放行；撤回硬规则不受影响 |
| `reply_cooldown_seconds` 同会话冷却秒数 | `0` | 回复结束后多少秒内不接同一会话下一条（含被点名）；默认 0 不限制，防刷屏填 10~30，可填 0~600 |
| `fail_open` 判断失败时是否放行 | 关 | 关：接口超时或报错就不回；开：宁可多发，打扰会变多 |
| `api_key` 接口密钥 | 空 | 只填在这一行，不要写进聊天偏好或任何地方 |
| `api_base` 接口地址 | 官方地址 | 只填地址本身，请求路径由插件补；必须是 https 公网地址 |
| `model` 模型名 | `jev-latest` | 三家叫法不同，见上表 |
| `timeout_seconds` 单次判断最多等几秒 | `8.0` | 可填 0.1~60，含排队时间，到点不重试 |
| `text_limit` 单条文本长度上限 | `2000` | 可填 100~4000，超了会截断 |
| `history_limit` 记录保留条数 | `1000` | 可填 1~10000，超出自动删最早的 |
## 预设闸门数值

每道题接口返回 0 到 1 的分数，档线决定「到没到」。默认「自定义闸门数值」是关的，下面每一项都不属于你碰的地方；这里列出来仅供你碰之前知道会动什么。记录里每次接话判断的四个分数是 `addressed`（是不是在叫我）、`continuation`（续话）、`worthwhile`（值得）、`intrusive`（打扰），复核三道是 `still_fits`（还合时宜）、`appropriate`（合适）、`redundant`（重复）；中英对照见下表第二列。

| 闸门 | 记录里的字段 | 什么作用 | 安静 | 平衡（默认） | 活泼 |
| --- | --- | --- | --- | --- | --- |
| 会打断就直接拦的线 | `intrusive` | 「会不会打断别人」分到这里直接不接 | 0.38 | 0.45 | 0.55 |
| 主动插话的打扰上限 | `intrusive` | 没人点名主动插话时，「打扰」得低于这条线 | 0.12 | 0.20 | 0.35 |
| 续话信任线 | `continuation` | 「接着刚才的话茬」到这里才认可在聊我 | 0.78 | 0.70 | 0.55 |
| 「是不是在叫我」信任线 | `addressed` | 没写 @ 也像在跟机器人说话才应点 | 0.86 | 0.80 | 0.70 |
| 「值得」入门线 | `worthwhile` | 续话 / 应点共用基础线：说了没价值不开口 | 0.56 | 0.50 | 0.42 |
| 主动插话的「值得」起评分 | `worthwhile` | 没人点名时主动插话要说得够有价值才开口（跟「打扰上限」一起用） | 0.86 | 0.78 | 0.70 |
| 复核「还合时宜」及格线 | `still_fits` | 生成期间新消息没让草稿过时 | 0.55 | 0.50 | 0.45 |
| 复核「合适」及格线 | `appropriate` | 草稿内容本身合不合适 | 0.80 | 0.75 | 0.70 |
| 复核「重复」上限 | `redundant` | 草稿跟上面聊过的重复不重复 | 0.25 | 0.35 | 0.45 |

想自己调：去配置页打开「自定义闸门数值（高级）」，展开填数，全部可填 0 到 1 的小数，填错范围插件启动时会报配置错误。想回预设：把开关关上即可，下面填过的数字还在，重新打开自定义开关又生效。

## 它是怎么判断的

- **七道题而不是一句问**：收到消息先问四道——是不是在叫我 / 是不是接着刚才的话茬 / 值不值得开口 / 会不会打断别人；复核时再问三道——还合时宜吗 / 合适吗 / 跟上面重复吗。每道题给 0~1 的分数，之后按固定规则合成结论，控制台历史里会写明是哪一个门拦的。
- **点名只问一道题**：被 @ 或以唤醒词开头的消息（统称点名），不问「会不会打扰」「是不是续话」，只问一道「值不值得开口」。光秃秃的点名、复读式点名、带辱骂的点名一般判不值得，机器人不接。
- **叫名字也算点名**：群里直接叫机器人名字（不用打 @）会被「是不是在叫我」这题识别成在叫它，只要内容值得就会接话。
- **接话合成规则**（在默认「参与程度 = 平衡」预设下）：打扰到 0.45 直接不接；接着话题的劲头足、说的又有价值就接着聊；明显是在跟我说话也接；没点名时想主动插话，得「很值得一说」且「几乎不打扰」。
- **判断时看到的聊天内容直接跟 AstrBot 走**：群聊先读 AstrBot 内置那份群聊记录；这份是空的，读上下文记录类插件提供的最近消息；还没有，本插件在被接管的会话里自己攒最近 20 条消息作兜底（只在内存里，重启清空）。私聊读当前会话已存的对话历史。
- **每次上传的就是三段可读文本**：当前这句（谁说的、什么场景）、前面的上下文（按时间正序）、准备发送的回复原文。平台名、会话 ID、消息 ID、人格编号这些内部信息不上传。
- **口味由你补充**：控制台里「聊天偏好」可以留空也可以写几行（所有阶段共用），填了会拼到每道题末尾。偏好里写了 `{{persona}}` 才会读取并发送当前会话生效的 AstrBot 人格提示词，没写就完全不发。

## 控制台

内嵌在 AstrBot 后台页里，三个页签：

- **判断历史**：每次判断的结果、逐项分数、拦截原因、耗时；点开能看到当次完整上下文和题目。
- **运行检查**：各开关当前状态、调用 Jev 的连接测试。
- **聊天偏好**：调口味的地方。下面带一个「高级：提示词覆写」折叠区——每个题卡里预填内置原文：改成别的话=替换题面；清空=这道题停用；每张卡有「填入内置原文」一键恢复。防注入提示由代码强制拼回，删不掉。

注意：**判断历史会原样记录聊天原文**，任何能登录 AstrBot 后台的人都能看。后台本身请放在受控网络里。
## 边界与隐私

- 接管哪些会话由 AstrBot 的两层白名单共同决定：会话白名单和主动回复白名单。任何一层填了名单且不命中，本插件完全不介入（不发请求、不读聊天内容、不改回复方式）。
- 被拒的接话消息只会掐断 AstrBot 默认的语言模型链路，**仍会交给其他插件处理**。
- 复核走 AstrBot 正常的回复链路。如果回复是工具调用的结果、别的插件绕过正常链路直接发送、或别的插件比本插件更晚才定夺发送方式，复核可能压不住。同时再启用别的主动回复插件可能冲突。
- 消息发到平台上之后的撤回无法追回；分段发送里已经发出去的那几段也收不回。
- 撤回拦截目前只支持 **OneBot v11** 协议的 QQ（群撤回和好友撤回），其他平台没有这项保护，也不作承诺。
- 判断记录存在插件数据目录下的本地数据库文件里，**没有加密**，含聊天原文。请妥善保管这台机器。

## 常见问题

- **关于已注册指令**：已注册指令照常执行、不经过判断。
- **又装了其他主动回复 / 唤醒类插件**：别同时开，两边同时接管会互相干扰。留一个。
- **判断记录里很多「判断服务故障」**：优先查接口地址和密钥是不是同一家服务的；再在控制台运行检查页点「调用 Jev 测试连接」，错误码会直接告诉我们。
- **换了接口后分数分布看不懂**：接口给出的分数可能跟官方接口的分布略有出入（尤其间隔时间长了再看），所以不建议一时兴起天天调档线；先在「影子模式」观察几天，再决定是否切自定义闸门。
- **以前装过老版本**：旧的 `threshold`（放行门槛）配置已取消，配置文件里残留的分值会被忽略；旧的两段提示词模板也自动迁移，残留的默认模板原文不会带进「聊天偏好」栏。
- **使用别的决策模型**：虽然名字叫 Jev 接话判断，但是 `POST /compatible-mode/v1/systemone` 的 decision-model-preview 也能使用
